# Build the client on Expo with a Skia SkPicture grid renderer

The mobile client is a React Native app on Expo with a development client and EAS builds, Expo Router navigation, and `@shopify/react-native-skia` as the stitch-grid renderer. This mirrors the stack proven in CrossCraft's frontend, so rendering, gesture, and background-service lessons transfer directly while the codebase, backend contracts, and data model remain fully independent under ADR-0014.

The grid renderer satisfies ADR-0031's interaction budget by drawing from recorded Skia pictures instead of re-issuing per-cell draw commands every frame. The stable visual state of the Pattern—cell fills, numbers, and grid lines—is recorded into SkPicture snapshots (tiled when the Pattern is large enough to warrant it). During pan, Anchored Zoom, and Stitch Sweep, each frame only replays the recorded pictures under the current viewport transform plus a small dynamic layer for cells changed by the active gesture; no picture re-recording, artifact decompression, or progress materialization runs inside the gesture. Changed regions are re-recorded incrementally after the gesture or between frames off the critical path. Scrolling and zooming therefore never wait on rebuilding the scene, which is the mechanism behind the 60 fps pan/zoom/sweep target and the 50 ms stitch-to-visible budget on the `300×300`, 60-color reference scenario.

We accept the Expo release train, Skia's native dependency weight, picture-cache memory management, tile-invalidation complexity, and renderer-specific performance work in exchange for a proven in-house stack, one navigation and build system across the team's projects, and a recorded-scene rendering model whose gesture path is independent of Pattern size.
