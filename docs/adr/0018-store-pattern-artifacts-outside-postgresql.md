# Store pattern artifacts outside PostgreSQL

Each immutable Pattern grid is encoded as a schema-versioned, compressed binary Pattern Artifact containing dimensions, the DMC palette, and cell-to-color indices. An S3-compatible object store holds the artifact bytes, while PostgreSQL stores Pattern identity, ownership, lifecycle state, searchable metadata, artifact object key, schema version, byte length, and checksum. Pattern Previews are separate image objects distributed through a CDN. Clients verify the artifact checksum before atomically persisting it as Offline Pattern Data and marking Session Preparation ready on that device.

Pattern Artifact version 1 uses a gzip-compressed Protocol Buffers envelope. Its grid is one row-major byte sequence: `0` represents an empty cell and `1..N` selects an entry in the included DMC palette. Pattern Previews are encoded as separate WebP images. This gives Python, NestJS, and React Native one explicit cross-runtime contract without per-cell objects or JSON parsing.

The object-store origin is private. After authorization, the Game Backend issues a short-lived Artifact Access Grant for any Pattern Artifact. Personal Pattern Previews also require owner-only signed access, while Official and Community Pattern Previews may be served from a public CDN for catalog browsing. Safety Removal stops new artifact grants and purges the public preview; Catalog Withdrawal may still grant the artifact to players whose existing sessions are allowed to continue.

We reject one database row per cell and large grid JSON columns: a Pattern may contain up to 90,000 cells, catalog content is read repeatedly, and immutable binary payloads can be cached and transferred more efficiently outside the transactional database. We accept object-storage lifecycle management, cross-store consistency, signed-delivery and CDN concerns, schema-aware client decoders, and orphan reconciliation in exchange for smaller PostgreSQL records, predictable downloads, immutable caching, and independent scaling of metadata and content bytes.
