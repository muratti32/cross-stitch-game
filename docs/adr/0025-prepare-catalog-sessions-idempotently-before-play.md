# Prepare catalog sessions idempotently before play

Starting an Official Pattern or Community Pattern requires connectivity and uses Session Preparation. The Game Backend authenticates either a Registered Account or Guest Installation Identity, validates current catalog availability and any required backend Pattern Unlock, then idempotently creates or returns that identity's one active Stitching Session for the Pattern and issues a short-lived Artifact Access Grant. The initiating device's background service downloads the Pattern Artifact and Pattern Preview, verifies the artifact checksum, atomically persists Offline Pattern Data, and completes the latest available Progress Merge. The session is Preparing and cannot open gameplay on that device until these steps succeed; Personal Patterns whose verified data already exists locally may start ready without this catalog-download flow.

Ready state is device-local rather than a global property of the backend session. When the same Registered Account opens an existing session on another device, that device runs Session Preparation against the same backend session identifier, obtains its own grant and Offline Pattern Data, and merges the latest available progress before play. It does not create a second Stitching Session or change whether the first device is ready. A Guest Installation Identity may own a backend session identity for authorization and idempotency, but its readiness and authoritative gameplay progress remain on that installation until Guest Data Promotion.

Download failure, connectivity loss, grant expiration, or checksum failure retains the same Preparing Session. Retrying obtains a fresh grant when necessary and resumes or restarts the transfer without creating another session identity. Partial or unverified data never becomes playable. Pattern Unlock purchase is a separate permanent entitlement, so a preparation failure cannot refund, consume again, or invalidate an already purchased unlock.

A Guest Data-Only Promotion may preserve progress for a non-free Official Pattern without transferring its Pattern Unlock. During identity switch the client deletes that session's Offline Pattern Data and the backend marks it Promotion-Locked, preventing artifact grants and gameplay. If the target account later acquires the Unlock, Session Preparation reuses that same session identity, downloads and verifies fresh Offline Pattern Data, and continues from the preserved progress rather than creating another attempt.

The Preparing interface offers Session Preparation Cancellation. Cancellation atomically stops the device-local transfer and removes temporary bytes. When preparation created a new backend session and that session has no progress on any device, the backend deletes the empty session idempotently. When the same session already has progress—for example because another device has played it—cancellation removes only the current device's preparation state and preserves the backend identity and all progress. In both cases any Pattern Unlock remains permanent.

We accept explicit local preparation state, background-transfer persistence, fresh-grant retries, atomic file replacement, cancellation races, empty-session cleanup, and orphaned Preparing-session cleanup in exchange for reliable offline play, no duplicate sessions, and a clear boundary between public preview caching and authorized playable bytes. The game may borrow implementation lessons from CrossCraft's background services, but this state and its backend records belong exclusively to the independent Game Backend.
