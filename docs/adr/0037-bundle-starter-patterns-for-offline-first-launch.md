# Bundle starter patterns for an offline first launch

A small set of free Official Patterns ships as Bundled Starter Patterns inside the app package: their Pattern Artifacts and Pattern Previews are embedded assets rather than downloads. A first launch without connectivity—previously a dead end, because the Guest Installation Identity, catalog, and Session Preparation all require the Game Backend—can therefore begin play immediately, and every first launch skips the download wait for its first stitch.

Starting a Bundled Starter Pattern is the sole exception to online Session Preparation for catalog content. The client creates a local Stitching Session that is Ready from the verified bundled bytes and records Progress Operations in the pre-identity Local Identity Namespace. At first connectivity the app obtains its Guest Installation Identity, idempotently registers the backend session identity for each locally started bundled session, and reconciles progress, Session Completion, and Pending Coin Rewards through the ordinary local-first rules; nothing about rewards, completion uniqueness, or promotion changes. Bundled artifacts carry the same checksums and schema version as downloaded ones, and the same Patterns remain in the server catalog so non-bundled devices and future app versions reach them normally. Safety Removal does not apply to operator-authored bundled content; retiring one from the bundle only stops future embedding and never invalidates existing sessions.

We accept larger app-package size, a release-time selection of bundled content, retroactive session registration, and one carefully bounded exception to the online preparation rule in exchange for a playable offline first launch, an onboarding path with zero download latency, and consistency with the principle that a generic connection screen never replaces usable local content.
