# Serve data access requests through support tooling

The first release satisfies data-subject access and portability requests (GDPR Articles 15 and 20 and equivalent regimes) through the support channel rather than an in-app self-service export. A player requests their data from support, support verifies the request against the authenticated account—using recent reauthentication or a Support Reference where applicable—and an operator runs a backend export tool that produces one machine-readable archive of the account's personal data: profile and Auth Identity metadata, Personal Pattern and AI Artwork inventories, Stitching Session progress and completion history, Likes, balances and Commerce Ledger grants, and moderation records the player is entitled to see. The export never includes another player's data, reporter identities, or internal fraud and security signals, and is delivered within the statutory deadline.

Guest Installation Identities are pseudonymous and installation-scoped; a Guest export request is served for the data reachable from the requesting installation's credential, and lost-credential requests cannot be honored because no recovery binding exists by design.

We accept manual operator work per request, a maintained export tool that must track schema changes, and a slower experience than self-service in exchange for legal compliance without building an async export pipeline, secure download delivery, and in-app flow into the first release. If request volume grows, a self-service export can be added later on top of the same export tool without changing what data the player is entitled to receive.
