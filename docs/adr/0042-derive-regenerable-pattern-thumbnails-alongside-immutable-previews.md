# Derive regenerable Pattern Thumbnails alongside immutable Pattern Previews

Every Pattern gains a second, decorative image: a Pattern Thumbnail that renders the grid as a finished cross-stitch piece — cross-stitch glyphs shaded from each cell's DMC Thread Color, laid on a fixed Aida fabric ground that also fills the cells the design leaves empty and the margin around a centred, non-square design. It is produced in two square variants from one deterministic backend renderer, and it is regenerable: a stored renderer version records which renderer produced it, and improving the renderer may reproduce existing Thumbnails in place. The existing Pattern Preview stays exactly as it is — an exact flat-pixel image of the grid — and remains the sole input to Catalog Technical Validation, Catalog Similarity Signal, and automated safety moderation.

We split the two rather than beautify the Pattern Preview because that image is load-bearing for moderation: `previewMatchesArtifact` asserts pixel-exact palette colours at an integer uniform scale, and stitch texture, shading, or antialiasing would fail it, so making previews attractive would mean weakening technical validation, perceptual-hash duplicate detection, and automated safety analysis at once — the opposite of ADR-0019. ADR-0016's rule that a new engine never regenerates a Pattern in place deliberately does not extend here: it protects playable content and post-moderation catalog snapshots, whereas a Thumbnail is neither, and being a deterministic function of an already-approved grid and palette it cannot surface anything a moderator did not already approve. ADR-0004 is likewise untouched — a Pattern's palette stays canonical DMC; only the Thumbnail's own pixels, its fabric ground, and its per-stitch shading are free of the DMC canon.

## Consequences

- Thumbnail generation never blocks a Pattern Conversion or a catalog publication. A failure leaves the Pattern fully usable and every browsing surface falls back to the Pattern Preview, so each such surface must carry that fallback.
- Because the fallback is now player-visible, the two existing preview renderers must agree on the empty-cell colour, which they currently do not (`conversion-engine` writes transparent, `backend` writes white).
- Object-key derivation moves into one place. Deletion, account closure, and Safety Removal paths currently enumerate `[artifactKey, previewKey]` by hand; with four objects per Pattern a missed entry leaves orphaned storage.
- No bulk regeneration job ships with this decision, because no Pattern rows exist yet. The renderer version is stored from the first migration regardless, since it cannot be reconstructed afterwards. Until that job exists, a missing or stale Thumbnail is corrected only by deleting and reconverting the Pattern.
- Bundled Starter Patterns embed the browsing variant only. Their Thumbnails freeze at build time, so a renderer upgrade leaves them visually inconsistent with the rest of the catalog until the next app release.
