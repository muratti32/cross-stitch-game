# Use passwordless email alongside Apple and Google authentication

Registered Accounts can be created and accessed through email, Apple, or Google. Email uses one passwordless flow for both sign-up and sign-in: the player proves access with a single-use six-digit code that expires after ten minutes, so the game stores no account passwords and needs no password-reset system. Request and verification attempts are rate-limited, and the request response does not disclose whether the address already exists. The first release omits Magic Links and their cross-device deep-link ambiguity. Each credential is an Auth Identity keyed by globally unique provider and provider subject, not by a mutable or shared email string. Matching email addresses never auto-link or merge accounts, including Apple private-relay addresses.

Adding or removing a provider uses explicit Auth Identity Link from an authenticated account after recent reauthentication. A provider already bound to another account is rejected, the final remaining sign-in method cannot be removed, and the first release never merges two Registered Accounts or transfers their content, balances, purchases, moderation state, or Guest Economy Promotion eligibility. This favors account-takeover resistance and auditable ownership over a convenient but dangerous email-based merge.

Device sessions use short-lived access tokens and rotating, device-scoped refresh tokens that the backend can revoke. Sign-out revokes that device session and locks its Local Identity Namespace without deleting unsynchronized records. Another Guest or Registered identity uses a different OS-protected namespace and cannot see the prior account's progress, drafts, Personal Patterns, Offline Pattern Data, or Ready states. Local Data Removal is a separate destructive confirmation; returning to the same account can otherwise reopen and reconcile its namespace.

Email, Apple, and Google authenticate one Account Cloud State in the Game Backend; they are not Google Drive, iCloud, or provider-specific backup stores. The first release has no independent Drive or iCloud export. We accept the resulting dependency on the Game Backend and explicit linking UX in exchange for one authoritative account, cross-device recovery through any linked method, no accidental account merge, and strict local data isolation.
