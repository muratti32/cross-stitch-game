# Reference shared catalog patterns from stitching sessions

Official and Community Patterns in the Pattern Catalog are immutable shared content. Starting one creates a player-owned Stitching Session that references the catalog Pattern and stores only player-specific Session Progress instead of cloning the grid and palette into another Pattern. This keeps attribution and content identity stable and avoids duplicating a large grid for every player, accepting that catalog-content retention and offline caching must preserve any Pattern still referenced by a session.

Starting an Official or Community Pattern uses online, idempotent Session Preparation. The Game Backend verifies current availability and any required Pattern Unlock, then creates or returns the player's one active Stitching Session for that Pattern and issues an Artifact Access Grant. The initiating device remains Preparing until its background service downloads the immutable grid, DMC palette, and preview, verifies the artifact checksum, and atomically stores them as Offline Pattern Data. Only then is the session Ready and playable on that device. A failed or interrupted download retries the same session with a refreshed grant instead of creating a duplicate, and a previously purchased Pattern Unlock remains permanent. Separately, Offline Catalog Cache may retain the last successfully fetched catalog pages as public metadata and previews for clearly marked, read-only offline browsing. That cache contains no Pattern Artifacts, grants no entitlement, performs no server search, and cannot start a new Stitching Session; catalog browsing never pre-downloads playable bytes.

Personal Patterns use the same reference rule even though they are owned rather than shared: a Stitching Session points to one immutable Personal Pattern instead of cloning its grid. Personal Pattern Editor saves create new Derived Personal Patterns, so editing cannot alter a session already in progress or its Offline Pattern Data.
